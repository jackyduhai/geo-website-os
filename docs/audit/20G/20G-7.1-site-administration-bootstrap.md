## 一、UX-002：Bootstrap 的真实缺口（4 个）

`SiteController@store` 原本已调用 4 个 Seeder：

```php

DefaultFormSeeder      → Forms
BlankHomepageSeeder    → 首页 Page
SystemPageSeeder       → 系统页
```

实测新站状态（建站后立即查库）：

| 项 | 实际 | 后果 |
|---|---|---|
| Settings | 92 行 ✅ | 后台设置页可遍历 |
| Pages | 有 ✅ | 首页可编辑 |
| **Categories** | **0 行** ❌ | 后台「新建内容」栏目下拉为空 |
| **Groups** | **0 行** ❌ | 内容无法归类 |
| **Menus / 导航可见性** | **0 行** ❌ | 前台显示工业制造口径项 |
| **`site_supported_locales`** | **`['zh-CN']`** ❌ | `/en/*` 严格 404（`SetLocale` 刻意行为） |

### 缺口 1：栏目 / 分组为空 —— 零代码建站契约断裂

`ContentController@formData` 取 `Category::with('children')->whereNull('parent_id')`，
0 行 → 运营建内容时无法归类。

### 缺口 2：导航暴露工业制造口径

主导航一级项来自 `config('copy.nav.menu')`：


对食品 / 服务类站点，`factory`（工厂与资质）与 `solutions`（应用场景）是**错误信息**。

### 缺口 3：语言开关只开 zh-CN

产品已确定 v1.0 = Multi-site × Multi-language，
新站保持单语言会让运营认为「英文功能坏了」。

### 缺口 4（**新发现，本轮最重要**）：`geo:install` 与后台建站**路径不等价**

## 二、修法：新增 `SiteStructureSeeder`（两条路径共用）

### 2.1 严格区分三类数据（20G-7.1 纪律）

| 类别 | 归属 | 本轮处理 |
|---|---|---|
| **站点级事实** | Settings | DefaultSettingSeeder 已覆盖 |
| **结构骨架** | categories / groups | 本 Seeder（行业中立） |
| **可见性决策** | menus | 本 Seeder（override 语义） |

**不 clone 默认站的运行时数据** —— 不复制它的 facts / domain / content / translation_group，
只用 `SiteContext::withSite($site)` 让新 Seeder 在新站的上下文里写全新行。

### 2.2 栏目结构：行业中立骨架

```
about      关于我们
products   产品中心
knowledge  知识中心 → groups: faq / guide
news       新闻动态 → groups: company-news / notice
contact    联系我们
```

刻意**不复用** `StructureSeeder` —— 那是演示数据（涂料 / 选型指南 / 工艺参数），
会把「涂料」塞进食品站。

### 2.3 导航：**只关掉，不覆盖**

`menus` 表有两种语义（踩坑点，见 `AppServiceProvider::mainMenuBlueprint`）：

| `key` | 语义 |
|---|---|
| 非空 | **覆盖**内置项（改 label / url / 启停） |
| 空 | **自定义新增**项 |

一级导航来自 `config`，**不是** menus 表。所以给 `factory` 建行 = 关闭它，
而不是「新增一个工厂导航」。

本 Seeder 只做克制的一步：为 `factory` / `solutions` 建 `is_active=false` 的 override，
**不改 label / url**（让内置文案继续走 `lang/` 翻译，运营启用后即恢复原名）。

### 2.4 站点隔离

`categories` / `groups` / `menus` 唯一约束均含 `site_id`：

```
categories  UNIQUE(site_id, slug)
groups      UNIQUE(site_id, category_id, slug)
menus       UNIQUE(site_id, key)
```

多站可安全使用**相同 slug**（E2E 的 `MS-001.slug-ok` 验证了 5 个 slug 跨站共存）。
匹配条件只给 `slug`，由 `SiteScope` 自动补 `site_id`。

### 2.5 两条路径接入

```php
// SiteController@store
(new \Database\Seeders\SiteStructureSeeder())->run();

// GeoInstall（4d-2 段）
$this->call('db:seed', ['--class' => 'SiteStructureSeeder', '--force' => true]);
```

## 三、幂等（BS-008）：`firstOrCreate` 而非 `updateOrCreate`

这是本轮最值得记的一个实现细节。

`updateOrCreate` 的真实实现（Laravel 12）：

```php
public function updateOrCreate(array $attributes, array $values = [])
{
    return tap($this->firstOrCreate($attributes, $values), function ($instance) use ($values) {
        if (! $instance->wasRecentlyCreated) {
            $instance->fill($values)->save();   // ← 已存在的行会被 values 覆盖
        }
    });
}
```

我最初用 `updateOrCreate` 并在注释里写「不覆盖人工修改」—— **认知是错的**。
E2E 的 `BS-008.no-overwrite` 立刻抓到：重跑 bootstrap 把「人工改过的栏目名」重置回「关于我们」。

修法：改用 `firstOrCreate`（只在匹配不到时用 values 新建，已存在则原样不动）。
**初始化是「补齐缺项」，不是「重置为出厂」。**

### 变异设计的两类无效（第8/9 条值得单独记）

**M2 无效的机制**：变异把栏目写死到 `site_id=1`，而 **A 站恰好就是站 1**（default 站）——
所以「写死到站 1」与正确版行为**完全等价**，E2E 32 条断言照样全绿。

> **判据：写变异前必须先确认「变异后的行为」与「正确行为」确实不同。**
> 挑一个恰好等于正确值的错误值，等于没变异。

**M5 被误判的机制**：M5 让 `Group::firstOrCreate` 漏掉 `category_id`，
实测确实破坏了行为（`NOT NULL constraint failed: groups.category_id`），
但 E2E 脚本**整体崩溃**，输出里没有 `[FAIL]` 行 → 被判 MISSED。

> **判据：变异测试的「捕获」判据必须包含「脚本非 0 退出」。**
> 崩溃本身就是行为被破坏的证据，不能因为「没看到断言红」就当没抓到。

## 六、变异测试：三类「假 MISSED」的根因

这一节是本轮方法论层面最重要的产出。5 条变异里有 2 条连续报 MISSED，
但**没有一条是真的「断言不足」** —— 全是变异机制本身的故障。

### 根因 1：CRLF vs LF —— 变异被静默跳过

源文件是 **CRLF**，注入片段是 **LF** → `str_replace` 永不匹配
→ 脚本 `sys.exit(3)` 跳过 → 看起来像「断言没守住」。

**识别信号**：注入后跑 E2E，输出与基线**逐字节一致**。
（若是真实的无效变异，输出也会一致 —— 所以这条信号只能证伪不能证实。）

修法：注入前先判断源文件换行符，归一后再replace，写回时还原。

配套工具：`docs/audit/20G/gates/verify-mutation-targets.php`
在任何注入式变异测试跑之前**先跑它**，把「片段写错」与「断言不足」分开。

### 根因 2：bash heredoc 吃掉反斜杠

注入串写成 `"...\$parent..."`，经 heredoc 传给 python 时反斜杠被吃掉
→ python 拿到 `$parent`（未定义变量）→ 匹配失败。

修法：bash 里含 `$` 的注入串**一律用单引号**，不做转义。

### 根因 3：变异值恰好等于正确值

| 版本 | 变异 | 为什么无效 |
|---|---|---|
| v1 | `site_id => 1` | A 站恰好就是站 1（default），行为等价 |
| v2 | `orderByDesc('id')` | B 站后建、id 最大，仍等于自己 |
| v3 | `site_id => 999999` | 触发 FK 约束，崩在 bootstrap 之前，断言根本没跑到 |
| 定稿 | 跨站串写（`site_id => 1` + `withoutSiteScope`） | 正常执行，行为真实改变 |

> **判据：写变异前必须先确认「变异后行为」≠「正确行为」。**
> 挑一个恰好等于正确值的错误值，等于没变异。

### 根因 4：脚本崩溃被判「断言全绿」

变异让 `Group::firstOrCreate` 漏 `category_id` → `NOT NULL constraint failed`
→ 脚本 fatal error。**但 PHP fatal 被 Laravel 异常处理器吞掉，进程退出码仍是 0**
→ 判 MISSED。

这与 20G-8「Laravel 吞迁移异常，退出码仍 0」是**同一类根因**：
**任何依赖退出码的判据在 Laravel 里都不可靠。**

修法（两处）：
1. E2E 脚本注册 `register_shutdown_function`，fatal 时写 `.crashed` 标记 + `exit(1)`
2. 变异脚本读**标记文件**判定，不只看退出码或 `[FAIL]` 行数
